Frameworks

The custom element works in every framework that renders HTML. The wrappers are thin: they create a controller on mount, pass changed props to set(), and destroy it on unmount.

Plain HTML

```html ```

Vanilla JavaScript

```js import { createBot } from '@kucukkanat/bots'; const bot = createBot(document.querySelector('#agent'), { type: 'droid', size: 96 }); bot.on('state', (e) => console.log('now', e.state)); ```

React

```jsx import { BotAvatar } from '@kucukkanat/bots/react'; export function Agent({ busy, onBot }) { return ( console.log(e.state)} /> ); } ```

Every option is a prop. Event props: onPoke, onBlink, onJump, onLand, onState. Props are compared by value, so re-rendering with the same props costs nothing. className and style go on the host element.

Vue

```vue ```

Options are props; the controller arrives with the ready event. You can also use <bot-avatar> directly; tell Vue it's a custom element with compilerOptions.isCustomElement = (tag) => tag === 'bot-avatar'.

Server rendering

Avatars draw on a canvas, so they only exist in the browser. Importing the module on the server is safe (nothing touches the DOM until an avatar is created), but create avatars in client-only code: useEffect, onMounted, onMount, or a client component in Next.js. Give the host a fixed width and height so nothing shifts when the avatar appears.

```jsx 'use client'; import { BotAvatar } from '@kucukkanat/bots/react'; ```
